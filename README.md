# Music Bot

Discord-бот с функциями в духе Spotify (поиск, очередь, плейлисты, избранное,
история, тексты песен), спроектированный под работу на **одном ядре CPU**
без зависаний.

## Важно про источники аудио

- **Реальный звук стримится с YouTube** через `yt-dlp` + `ffmpeg`.
- **Spotify** используется только как источник метаданных: ссылку на трек/
  альбом/плейлист Spotify бот резолвит в список "исполнитель — название" и
  ищет соответствующее аудио на YouTube. Официальный Spotify API **не
  отдаёт аудиопоток** сторонним приложениям — так что "бота, который дословно
  играет с серверов Spotify" в природе не существует, все музыкальные боты
  на самом деле работают так же.
- **Genius** (опционально) даёт короткое превью текста песни + ссылку на
  полный текст — специально не выводим текст целиком, это охраняется
  авторским правом.

## Архитектура и почему это быстро на 1 ядре

- **Node.js/TypeScript + discord.js** — однопоточный event loop идеально
  ложится на одно ядро: не тратим время на переключение контекста между
  потоками, как было бы в модели thread-per-connection.
- Реальная нагрузка (декод/энкод аудио) уходит в **нативные процессы**:
  `ffmpeg` тянет аудио напрямую по HTTP из уже резолвленного URL (без
  промежуточного файла и без второго процесса на скачивание), а Opus-энкодинг
  делает нативный `@discordjs/opus` (биндинг к libopus, C-код). JS-поток
  только дирижирует, не считает.
- **Никакого Lavalink** (отдельная JVM) — на одном ядре это чистый
  оверхед (память, GC, прогрев), не оправданный для скромного числа гильдий.
- **better-sqlite3** — встроенная синхронная БД, без отдельного процесса.
- **LRU-кэш** поисковых запросов (`quick-lru`), чтобы не дёргать `yt-dlp`
  повторно на одинаковые запросы.
- **Автодополнение `/play`** берёт подсказки из избранного/истории (мгновенно,
  локально), а не гоняет живой поиск по YouTube на каждое нажатие клавиши —
  иначе автодополнение само стало бы источником лагов.
- **Идле-таймеры**: авто-выход из голосового канала, если бот там один или
  очередь пуста дольше `IDLE_LEAVE_MINUTES` — освобождает соединения/процессы.
- Жёсткое убийство ffmpeg-процесса (`SIGKILL`) при skip/stop/ошибке —
  никаких "зомби"-процессов, которые копятся и едят CPU.
- `docker-compose.yml` жёстко ограничивает контейнер 1 CPU / 512MB, чтобы
  сразу было видно на реальном железе, укладывается ли бот в бюджет.

## Функционал

- `/play` — поиск/ссылка YouTube/ссылка Spotify, автодополнение
- `/skip`, `/pause`, `/resume`, `/stop`
- `/queue`, `/remove`, `/loop`, `/shuffle`, `/volume`
- `/nowplaying` — карточка с кнопками (пауза/скип/стоп/повтор/шаффл)
- `/playlist save|load|list|delete|add` — персональные плейлисты (sqlite)
- `/favorite add|remove|list` — избранное
- `/history` — недавно сыгранные треки на сервере
- `/lyrics` — превью текста песни + ссылка на Genius
- `/autoplay on|off` — когда очередь заканчивается, сам подбирает похожие треки (YouTube Mix от последнего сыгранного) — аналог радио/автовоспроизведения в Spotify
- `/seek 1:30` — перемотать текущий трек (форматы: `90`, `1:30`, `1:05:20`, относительно — `+15`/`-15`)

## Быстрый старт (Docker — рекомендуемый способ)

1. Скопируй `.env.example` в `.env` и заполни минимум `DISCORD_TOKEN` и
   `DISCORD_CLIENT_ID` (создать приложение: https://discord.com/developers/applications).
2. Зарегистрируй slash-команды:
   ```bash
   npm install
   npm run deploy-commands
   ```
   (Для мгновенного появления команд на время разработки укажи в `.env`
   `DISCORD_DEV_GUILD_ID` — id твоего тестового сервера.)
3. Собери и запусти контейнер:
   ```bash
   docker compose up -d --build
   ```
4. Логи: `docker compose logs -f`.

## Локальный запуск без Docker

Нужны установленные `ffmpeg` и `yt-dlp` в PATH.

```bash
npm install
cp .env.example .env   # заполнить токены
npm run deploy-commands
npm run dev             # разработка (hot reload)
# или
npm run build && npm start   # прод-сборка
```

## Возрастные ограничения на YouTube

Часть видео с пометкой 18+ YouTube не отдаёт анонимно — только залогиненным
аккаунтам. Чтобы бот мог их проигрывать, задай `YTDLP_COOKIES_FILE` — путь
к `cookies.txt` (формат Netscape), экспортированному из браузера с
залогиненным YouTube (например, расширением "Get cookies.txt LOCALLY").
Без этой переменной всё остальное работает как обычно, просто такие видео
будут пропускаться с ошибкой. Файл куки — это фактически ключ от сессии
аккаунта: держи права `600`, владельца — тем же uid, что у процесса в
контейнере (uid 1000, "node" — иначе `Permission denied` на чтение),
никогда не клади в git (уже в `.gitignore`). В Docker — пробрось отдельным
volume (см. закомментированную строку в `docker-compose.yml`), и **не
монтируй `:ro`** — yt-dlp периодически дозаписывает обновлённые
session-куки обратно в тот же файл, read-only тут даёт `OSError:
Read-only file system` на каждом вызове (реальный инцидент, см.
[CLAUDE.md](CLAUDE.md)). Региональные блокировки (когда лейбл закрыл видео
для конкретной страны) куки не лечат — это зависит от IP сервера, а не от
авторизации.

## Опциональные интеграции

- **Spotify** (`/play <ссылка spotify.com>`, `/playlist add` со ссылкой):
  задать `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET` — Client Credentials
  Flow, приложение создаётся на https://developer.spotify.com/dashboard.
  Без них ссылки Spotify просто не будут распознаваться.
- **Genius** (`/lyrics`): задать `GENIUS_ACCESS_TOKEN` —
  https://genius.com/api-clients. Без него команда ответит, что не настроена.

## Обслуживание

- `yt-dlp` собирается в Docker-образ на этапе сборки из релиза "latest".
  YouTube регулярно меняет внутренние механизмы — если поиск/проигрывание
  перестало работать, пересобери образ (`docker compose build --no-cache`),
  чтобы подтянуть свежий `yt-dlp`.
- База данных лежит в `./data/musicbot.db` (том Docker) — бэкапь её при
  необходимости, это единственное персистентное состояние бота.
